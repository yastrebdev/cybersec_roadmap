# IPv4, маски и подсети

## Что даст эта глава

После чтения ты сможешь:

- разбирать IPv4-адрес на сетевую и узловую части;
- понимать записи `/8`, `/16`, `/24` и другие префиксы;
- находить адрес сети, broadcast и диапазон узлов;
- определять, находятся ли два адреса в одной подсети;
- понимать частные, публичные и специальные адреса.

## Структура IPv4-адреса

IPv4-адрес содержит 32 бита. Для удобства их записывают четырьмя десятичными числами от `0` до `255`:

```text
192.168.56.10
```

Каждое число представляет 8 бит, то есть один октет:

```text
192      168      56       10
8 бит    8 бит    8 бит    8 бит
```

Всего получается 32 бита.

Сам по себе адрес не сообщает размер сети. Поэтому рядом указывают маску или длину префикса:

```text
192.168.56.10/24
```

## Сетевая и узловая части

Часть битов обозначает сеть, остальные — конкретный интерфейс внутри сети.

В записи `/24`:

- первые 24 бита — сеть;
- последние 8 бит — узел.

Для адреса `192.168.56.10/24`:

```text
Сеть: 192.168.56
Узел:          10
```

Адрес сети:

```text
192.168.56.0/24
```

## Маска подсети

Префикс `/24` соответствует маске:

```text
255.255.255.0
```

Единицы маски обозначают сетевые биты, нули — узловые.

```text
11111111.11111111.11111111.00000000
```

Каждый заполненный октет `11111111` равен `255`.

Частые соответствия:

| CIDR | Маска | Всего адресов |
|---|---|---|
| `/8` | `255.0.0.0` | 16 777 216 |
| `/16` | `255.255.0.0` | 65 536 |
| `/24` | `255.255.255.0` | 256 |
| `/25` | `255.255.255.128` | 128 |
| `/26` | `255.255.255.192` | 64 |
| `/27` | `255.255.255.224` | 32 |
| `/28` | `255.255.255.240` | 16 |
| `/29` | `255.255.255.248` | 8 |
| `/30` | `255.255.255.252` | 4 |

Формула количества адресов:

```text
2^(32 - длина префикса)
```

Для `/24`:

```text
2^(32 - 24) = 2^8 = 256
```

## Адрес сети и broadcast

В обычной IPv4-подсети два адреса имеют специальное назначение.

Первый адрес — идентификатор сети:

```text
192.168.56.0
```

Последний адрес — directed broadcast этой сети:

```text
192.168.56.255
```

Обычным узлам остаётся диапазон:

```text
192.168.56.1–192.168.56.254
```

Поэтому у `/24` всего 256 адресов, но в традиционной подсети — 254 адреса для узлов.

## Как определить одну подсеть

Сравним:

```text
Kali:          192.168.56.10/24
Metasploitable: 192.168.56.20/24
```

У обоих первые 24 бита одинаковы: `192.168.56`. Значит, они находятся в одной подсети и могут общаться напрямую на канальном уровне.

Теперь другой адрес:

```text
192.168.57.20/24
```

Его сеть — `192.168.57.0/24`. Для связи между этими сетями потребуется маршрутизатор.

## Подсети, граница которых не совпадает с октетом

С `/24` всё просто, потому что граница проходит между октетами. Рассмотрим:

```text
192.168.56.130/26
```

У `/26` остаётся 6 бит для узлов:

```text
2^6 = 64 адреса
```

Размер блока — 64. Подсети последнего октета начинаются с:

```text
0, 64, 128, 192
```

Адрес `130` попадает в блок `128–191`.

Следовательно:

```text
Адрес сети:   192.168.56.128/26
Первый узел:  192.168.56.129
Последний:    192.168.56.190
Broadcast:    192.168.56.191
```

## Быстрый метод размера блока

Если маска последнего значимого октета равна `192`:

```text
256 - 192 = 64
```

Размер каждого блока — 64 адреса.

Для `/27` маска `255.255.255.224`:

```text
256 - 224 = 32
```

Подсети начинаются с:

```text
0, 32, 64, 96, 128, 160, 192, 224
```

Для адреса `192.168.1.77/27`:

```text
Сеть:      192.168.1.64
Broadcast: 192.168.1.95
Узлы:      192.168.1.65–192.168.1.94
```

## Проверка через Linux

Утилита `ipcalc` помогает проверить расчёт:

```bash
ipcalc 192.168.56.130/26
```

Если она не установлена:

```bash
sudo apt update
sudo apt install ipcalc
```

Сначала попробуй посчитать вручную, затем используй инструмент для проверки.

## Частные IPv4-диапазоны

Для внутренних сетей зарезервированы диапазоны:

| Диапазон | CIDR |
|---|---|
| `10.0.0.0–10.255.255.255` | `10.0.0.0/8` |
| `172.16.0.0–172.31.255.255` | `172.16.0.0/12` |
| `192.168.0.0–192.168.255.255` | `192.168.0.0/16` |

Эти адреса не маршрутизируются в глобальном интернете как обычные публичные адреса. Домашние сети и лаборатории обычно используют именно их.

`192.168.56.0/24` входит в частный диапазон `192.168.0.0/16`.

## Другие специальные адреса

`127.0.0.0/8` — loopback. Обычно используется `127.0.0.1`:

```text
Этот компьютер обращается к самому себе.
```

`169.254.0.0/16` — link-local. Такой адрес может появиться, если узел не получил обычную конфигурацию, например от DHCP.

`0.0.0.0` имеет несколько контекстных значений. В маршруте `0.0.0.0/0` означает любое IPv4-направление. У слушающего сервиса `0.0.0.0` обычно означает все локальные IPv4-интерфейсы.

`255.255.255.255` — ограниченный broadcast текущего сегмента.

## Почему пентестеру нужны подсети

Без понимания CIDR легко:

- просканировать неправильный диапазон;
- выйти за разрешённый scope;
- пропустить часть адресов;
- принять адрес сети за адрес узла;
- неправильно настроить виртуальную лабораторию;
- не понять, почему узлы не видят друг друга.

Запись scope `192.168.56.0/24` означает весь диапазон этой лабораторной подсети, а не конкретную машину.

## Практика на своей лаборатории

Посмотри адреса:

```bash
ip -br addr
```

Найди Host-only адрес, например:

```text
192.168.56.10/24
```

Ответь:

1. Какой адрес сети?
2. Какой broadcast?
3. Какой диапазон обычных узлов?
4. Входит ли `192.168.56.200` в эту сеть?
5. Входит ли `192.168.57.10`?

Проверь вычисление:

```bash
ipcalc 192.168.56.10/24
```

## Упражнения

Для каждого адреса найди сеть, broadcast и диапазон узлов:

```text
10.0.2.15/24
192.168.1.70/26
172.16.5.200/27
192.168.100.14/28
```

Ответы для самопроверки:

| Адрес | Сеть | Broadcast |
|---|---|---|
| `10.0.2.15/24` | `10.0.2.0` | `10.0.2.255` |
| `192.168.1.70/26` | `192.168.1.64` | `192.168.1.127` |
| `172.16.5.200/27` | `172.16.5.192` | `172.16.5.223` |
| `192.168.100.14/28` | `192.168.100.0` | `192.168.100.15` |

## Что важно запомнить

- IPv4 содержит 32 бита.
- CIDR-префикс определяет количество сетевых битов.
- Маска нужна для разделения адреса на сеть и узел.
- `/24` содержит 256 адресов.
- Первый адрес обычно обозначает сеть, последний — broadcast.
- Устройства определяют локальность цели с помощью адреса и маски.
- Частные адреса используются во внутренних сетях.
