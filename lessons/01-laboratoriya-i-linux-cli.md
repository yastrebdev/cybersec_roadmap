## Правила безопасной практики

Все упражнения выполняй только:

- на собственных виртуальных машинах;
- в намеренно уязвимых лабораториях;
- на системах, для которых у тебя есть явное разрешение;
- внутри изолированной виртуальной сети.

Не подключай намеренно уязвимую машину через `Bridged Adapter`. В таком режиме она может оказаться доступной другим устройствам локальной сети.

Не используй команды и инструменты из урока для проверки чужих адресов, серверов или сетей.

# Часть 2. Модель лаборатории

Рекомендуемая схема:

```text
                         Интернет
                            |
                         NAT-сеть
                            |
                    +----------------+
                    | Рабочая Linux  |
                    | Kali / Ubuntu  |
                    |                |
                    | NAT adapter    |
                    | Host-only      |
                    +-------+--------+
                            |
                     Host-only сеть
                       192.168.56.0/24
                            |
                    +-------+--------+
                    | Учебная цель   |
                    | Ubuntu Server  |
                    |                |
                    | Только         |
                    | Host-only      |
                    +----------------+
```

Рабочая машина получает:

- NAT-адаптер для обновлений;
- Host-only адаптер для взаимодействия с лабораторией.

Учебная цель получает:

- только Host-only адаптер;
- отсутствие прямого доступа из домашней или офисной сети.

## Почему не Bridged

Режим Bridged подключает виртуальную машину почти как отдельное физическое устройство локальной сети.

Для намеренно уязвимой машины это опасно:

- её могут увидеть другие устройства;
- её службы могут оказаться доступны вне лаборатории;
- ошибки настройки затронут не только виртуальную среду.

# Часть 3. Создание виртуальных машин

## Рабочая машина

Рекомендуемые параметры:

- 2 процессорных ядра;
- 3–4 ГБ RAM;
- 30–40 ГБ диска;
- один NAT-адаптер;
- один Host-only адаптер.

После установки проверь интерфейсы:

```bash
ip address
```

Посмотри маршруты:

```bash
ip route
```

Проверь DNS:

```bash
cat /etc/resolv.conf
```

Проверь доступ в интернет:

```bash
ping -c 3 1.1.1.1
```

Затем проверь разрешение доменного имени:

```bash
getent hosts example.com
```

Если IP-адрес пингуется, а доменное имя не разрешается, вероятная проблема находится в DNS.

## Учебная цель

Рекомендуемые параметры:

- 1–2 процессорных ядра;
- 1–2 ГБ RAM;
- 15–20 ГБ диска;
- только Host-only адаптер.

Узнай IP-адрес цели:

```bash
ip address
```

Предположим, цель получила адрес:

```text
192.168.56.20
```

С рабочей машины проверь доступность:

```bash
ping -c 3 192.168.56.20
```

Если ответа нет, последовательно проверь:

1. Запущены ли обе машины.
2. Подключены ли адаптеры к одной Host-only сети.
3. Назначены ли адреса из одной подсети.
4. Не блокирует ли ICMP локальный firewall.
5. Существует ли корректный маршрут.

# Часть 7. Пользователи и права

Текущий пользователь:

```bash

```

Информация о пользователях:

```bash

```

Информация о группах:

```bash
getent group
```

## Интерпретация прав

Пример:

```text
-rw-r----- 1 alice analysts 1024 Sep 27 report.txt
```

Разбор:

```text
-          обычный файл
rw-        владелец может читать и изменять
r--        группа может читать
---        остальные не имеют доступа
alice      владелец
analysts   группа
```

## Символьная запись

```bash
chmod u+x scripts/auth_summary.py
chmod g+r samples/auth.log
chmod o-rwx samples/auth.log
```

## Числовая запись

| Значение | Право |
|---:|---|
| 4 | Чтение |
| 2 | Запись |
| 1 | Выполнение |

Примеры:

```bash
chmod 600 samples/auth.log
chmod 640 samples/auth.log
chmod 755 scripts/auth_summary.py
```

Не устанавливай `777`, чтобы «просто заработало». Сначала определи, кому действительно необходим доступ.

# Часть 11. Python-практика: парсер журнала входов

## Задача

Написать CLI-инструмент, который:

1. Принимает путь к журналу.
2. Находит неуспешные попытки SSH-входа.
3. Группирует события по IP-адресу.
4. Группирует события по имени пользователя.
5. Показывает итог в терминале.
6. При необходимости сохраняет JSON.
7. Корректно обрабатывает отсутствующий файл.

Для задачи используется только стандартная библиотека Python.

## Тестовый журнал

Сохрани следующий текст в `samples/auth.log`:

```text
Sep 27 10:01:14 lab sshd[1001]: Failed password for invalid user admin from 192.168.56.31 port 51244 ssh2
Sep 27 10:01:21 lab sshd[1002]: Failed password for root from 192.168.56.31 port 51251 ssh2
Sep 27 10:02:02 lab sshd[1003]: Accepted password for student from 192.168.56.10 port 51320 ssh2
Sep 27 10:03:45 lab sshd[1004]: Failed password for student from 192.168.56.44 port 51511 ssh2
Sep 27 10:04:01 lab sshd[1005]: Failed password for root from 192.168.56.31 port 51550 ssh2
```

## Реализация

Создай `scripts/auth_summary.py`:

```python
#!/usr/bin/env python3

import argparse
import json
import re
from collections import Counter
from pathlib import Path


FAILED_LOGIN = re.compile(
    r"Failed password for "
    r"(?:invalid user )?"
    r"(?P<username>\S+) "
    r"from (?P<ip>\d{1,3}(?:\.\d{1,3}){3})"
)


def parse_arguments() -> argparse.Namespace:
    parser = argparse.ArgumentParser(
        description="Summarize failed SSH login attempts."
    )
    parser.add_argument(
        "log_file",
        type=Path,
        help="Path to the authentication log",
    )
    parser.add_argument(
        "--json-out",
        type=Path,
        help="Optional path for the JSON report",
    )
    return parser.parse_args()


def analyze_log(log_file: Path) -> dict:
    if not log_file.exists():
        raise FileNotFoundError(f"File does not exist: {log_file}")

    if not log_file.is_file():
        raise ValueError(f"Path is not a regular file: {log_file}")

    ip_counts: Counter[str] = Counter()
    user_counts: Counter[str] = Counter()
    matched_events = 0

    with log_file.open(
        "r",
        encoding="utf-8",
        errors="replace",
    ) as source:
        for line in source:
            match = FAILED_LOGIN.search(line)

            if match is None:
                continue

            matched_events += 1
            ip_counts[match.group("ip")] += 1
            user_counts[match.group("username")] += 1

    return {
        "source": str(log_file),
        "failed_login_events": matched_events,
        "by_ip": dict(ip_counts.most_common()),
        "by_username": dict(user_counts.most_common()),
    }


def print_report(report: dict) -> None:
    print(f"Source: {report['source']}")
    print(f"Failed login events: {report['failed_login_events']}")

    print("\nBy IP:")
    for ip, count in report["by_ip"].items():
        print(f"  {ip}: {count}")

    print("\nBy username:")
    for username, count in report["by_username"].items():
        print(f"  {username}: {count}")


def save_json(report: dict, destination: Path) -> None:
    destination.parent.mkdir(parents=True, exist_ok=True)
    destination.write_text(
        json.dumps(report, indent=2, ensure_ascii=False),
        encoding="utf-8",
    )


def main() -> int:
    args = parse_arguments()

    try:
        report = analyze_log(args.log_file)
    except (FileNotFoundError, PermissionError, ValueError) as error:
        print(f"Error: {error}")
        return 1

    print_report(report)

    if args.json_out is not None:
        save_json(report, args.json_out)
        print(f"\nJSON report saved to: {args.json_out}")

    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Сделай файл исполняемым:

```bash
chmod 755 scripts/auth_summary.py
```

Посмотри справку:

```bash
python3 scripts/auth_summary.py --help
```

Запусти анализ:

```bash
python3 scripts/auth_summary.py samples/auth.log
```

Сохрани JSON:

```bash
python3 scripts/auth_summary.py \
  samples/auth.log \
  --json-out evidence/auth-summary.json
```

Ожидаемый результат:

```text
Source: samples/auth.log
Failed login events: 4

By IP:
  192.168.56.31: 3
  192.168.56.44: 1

By username:
  root: 2
  admin: 1
  student: 1
```
