# Диагностика сети в Linux

## Что даст эта глава

После чтения ты сможешь:

- проверять сеть в правильном порядке;
- понимать назначение `ip`, `ping`, `ss`, `dig`, `curl` и `nmap -sn`;
- отличать проблему интерфейса от проблемы DNS или приложения;
- собрать минимальные доказательства для учебного журнала;
- проверить связь Kali и Metasploitable без глубокого сканирования.

## Главный принцип

Не запускай случайный набор инструментов. Каждая команда должна отвечать на конкретный вопрос.

```text
Интерфейс включён?
  ↓
Адрес назначен?
  ↓
Маршрут существует?
  ↓
Сосед или шлюз доступен?
  ↓
Имя разрешается?
  ↓
Нужный порт доступен?
  ↓
Приложение отвечает правильно?
```

Если перескочить через уровни, легко сделать неправильный вывод. Например, неработающий `curl` ещё не означает проблему веб-сервера: возможно, неверен DNS или отсутствует маршрут.

## Шаг 1. Интерфейсы и адреса

```bash
ip -br addr
```

Команда показывает интерфейс, состояние и адреса:

```text
lo      UNKNOWN  127.0.0.1/8 ::1/128
eth0    UP       10.0.2.15/24
eth1    UP       192.168.56.10/24
```

Проверь:

- существует ли нужный интерфейс;
- находится ли он в состоянии `UP`;
- назначен ли IPv4-адрес;
- совпадает ли подсеть с ожидаемой.

Подробный вывод:

```bash
ip addr show eth1
```

Канальное состояние и MAC:

```bash
ip link show eth1
```

Если интерфейс отсутствует, сначала проверяй настройки VirtualBox. Если интерфейс есть, но адреса нет, проверяй DHCP или статическую конфигурацию.

## Почему не `ifconfig`

`ifconfig` всё ещё встречается и может быть установлен:

```bash
ifconfig -a
```

Но современный Linux использует набор `iproute2`:

| Старый инструмент | Современная команда |
|---|---|
| `ifconfig` | `ip addr`, `ip link` |
| `route -n` | `ip route` |
| `arp -n` | `ip neigh` |
| `netstat` | `ss` |

На старой Metasploitable `ifconfig` может быть привычнее или доступнее, поэтому его вывод понимать полезно.

## Шаг 2. Маршруты

```bash
ip route
```

Пример:

```text
default via 10.0.2.1 dev eth0
10.0.2.0/24 dev eth0 src 10.0.2.15
192.168.56.0/24 dev eth1 src 192.168.56.10
```

Проверь, что лабораторная сеть направлена в Host-only интерфейс.

Узнать выбранный маршрут до цели:

```bash
ip route get 192.168.56.20
```

Пример:

```text
192.168.56.20 dev eth1 src 192.168.56.10
```

Если команда выбирает не тот интерфейс, проблема находится в адресации или таблице маршрутизации.

## Шаг 3. Соседи локальной сети

```bash
ip neigh
```

Пример:

```text
192.168.56.20 dev eth1 lladdr 08:00:27:12:34:56 STALE
```

Таблица содержит устройства, с которыми система уже взаимодействовала. Она не является полным сканированием сети.

Если запись отсутствует, сначала создай трафик:

```bash
ping -c 1 192.168.56.20
ip neigh
```

Состояние `FAILED` может означать неправильный адрес, выключенную машину, другой виртуальный сегмент или отключённый кабель.

## Шаг 4. Проверка связи через ICMP

```bash
ping -c 4 192.168.56.20
```

`-c 4` ограничивает проверку четырьмя запросами.

Успешная сводка:

```text
4 packets transmitted, 4 received, 0% packet loss
```

Полезные показатели:

- packet loss — доля потерянных ответов;
- time — задержка туда и обратно;
- duplicate — повторные ответы;
- unreachable — сообщение о недостижимости.

Отсутствие ответа не доказывает, что узел выключен. ICMP может блокироваться. В собственной Host-only лаборатории ответы обычно разрешены, поэтому `ping` удобен для первичной проверки.

## Шаг 5. Обнаружение устройств

Если IP цели неизвестен:

```bash
nmap -sn -n 192.168.56.0/24
```

Параметры:

- `-sn` — обнаружение хостов без портового сканирования;
- `-n` — не пытаться определять DNS-имена;
- `192.168.56.0/24` — проверяемая лабораторная подсеть.

Пример:

```text
Nmap scan report for 192.168.56.1
Host is up.

Nmap scan report for 192.168.56.10
Host is up.

Nmap scan report for 192.168.56.20
Host is up.
```

В списке могут быть:

- виртуальный адаптер Windows;
- Kali;
- Metasploitable;
- служебные узлы VirtualBox.

Сканируй только собственную Host-only сеть. Не подставляй адрес публичной или чужой сети.

## Шаг 6. Сокеты собственной машины

```bash
sudo ss -lntup
```

Команда отвечает на вопрос: какие сервисы Kali сейчас принимает?

Параметры:

- `-l` — слушающие сокеты;
- `-n` — числовые адреса и порты;
- `-t` — TCP;
- `-u` — UDP;
- `-p` — процессы.

Пример:

```text
LISTEN 0 128 127.0.0.1:8000 0.0.0.0:* users:(("python3",pid=1200,fd=3))
```

Это локальная проверка Kali, а не сканирование Metasploitable.

## Шаг 7. DNS

Если проблема связана с доменным именем:

```bash
dig example.com
```

Краткий ответ:

```bash
dig +short example.com
```

Сравни:

```bash
ping -c 2 example.com
ping -c 2 <полученный-IP>
```

Если IP доступен, а имя не разрешается, вероятная область проблемы — DNS.

Для Host-only адреса Metasploitable DNS обычно не нужен: можно обращаться непосредственно по IP.

## Шаг 8. Проверка конкретного TCP-порта

Когда ты уже знаешь, что должен быть доступен определённый сервис:

```bash
nc -vz 192.168.56.20 80
```

Параметры:

- `-v` — подробный вывод;
- `-z` — проверить подключение без передачи обычных данных.

Возможные результаты:

```text
succeeded
```

TCP-соединение установлено.

```text
Connection refused
```

Узел ответил, но порт закрыт или сервис не слушает.

```text
timed out
```

Ответ не получен: возможны фильтрация, неправильный маршрут или недоступность узла.

Это уже точечная проверка известного сервиса, а не глубокое исследование портов.

## Шаг 9. Проверка приложения

Если ожидается HTTP:

```bash
curl -I http://192.168.56.20
```

Команда запрашивает заголовки и показывает статус сервера.

Подробный обмен:

```bash
curl -v http://192.168.56.20/
```

`curl` проверяет уже прикладной протокол. Успешный TCP-connect ещё не гарантирует правильный HTTP-ответ.

## `nmap -sn` и `ip neigh` — не одно и то же

`ip neigh` показывает локальный кэш уже известных соседей.

`nmap -sn` активно пытается найти работающие узлы в выбранном диапазоне.

Поэтому:

```text
ip neigh  → что система уже знает
nmap -sn  → какие узлы можно обнаружить сейчас
```

## Минимальная проверка лаборатории

Если задача — только убедиться, что Kali и Metasploitable видят друг друга:

```bash
ip -br addr
ip route
nmap -sn -n 192.168.56.0/24
ping -c 4 192.168.56.20
ip neigh
```

Этого достаточно. `whois`, `theHarvester`, Sherlock и другие OSINT-инструменты для этой задачи не нужны.

## Диагностические сценарии

### Интерфейс Host-only не появился

Проверяй:

1. Виртуальная машина полностью выключалась перед настройкой?
2. Включён ли второй адаптер Kali?
3. Выбран ли тип Host-only?
4. Отмечен ли виртуальный кабель?
5. Запущена ли машина после изменений?

### Интерфейс есть, но IPv4 нет

Проверяй:

1. Включён ли DHCP для Host-only сети?
2. Получила ли Metasploitable адрес?
3. Нет ли ручной конфигурации из другой подсети?

Можно запросить аренду повторно:

```bash
sudo dhclient -v eth1
```

Подставь фактическое имя Host-only интерфейса.

### У обеих машин адреса есть, но `ping` не работает

Проверяй:

1. Одинаковы ли первые 24 бита при маске `/24`?
2. Выбран ли один и тот же Host-only адаптер?
3. Есть ли маршрут локальной сети?
4. Появляется ли сосед в `ip neigh`?
5. Не блокируется ли ICMP firewall.

### IP работает, домен нет

Проверяй DNS:

```bash
cat /etc/resolv.conf
dig example.com
```

### `ping` работает, приложение нет

Проверяй конкретный порт и протокол:

```bash
nc -vz 192.168.56.20 80
curl -v http://192.168.56.20/
```

## Как вести запись

Не сохраняй весь терминал без разбора. Записывай вопрос, команду, ключевой результат и вывод.

```markdown
## Проверка лабораторной сети

Вопрос: видит ли Kali Metasploitable?

Команда: ping -c 4 192.168.56.20

Результат: 4 ответа, потерь нет.

Вывод: базовая IP-связность работает.
```

Такая запись полезнее, чем сотни строк необъяснённого вывода.

## Что важно запомнить

- Каждая команда должна отвечать на конкретный вопрос.
- Начинай с интерфейса и адреса, а не с приложения.
- `ip route get` показывает фактически выбранный путь.
- `ip neigh` — кэш соседей, не список всей сети.
- `ping` проверяет ICMP-связность, но не конкретный сервис.
- `nmap -sn` обнаруживает хосты без сканирования портов.
- `ss` показывает сокеты локальной машины.
- `dig` проверяет DNS, `curl` — HTTP.

## Финальная практика

Не подглядывая в текст, выполни базовую проверку:

1. Найди Host-only интерфейс Kali.
2. Назови её IP и подсеть.
3. Покажи маршрут до Metasploitable.
4. Найди Metasploitable без проверки портов.
5. Проверь ICMP-связь.
6. Покажи соответствие IP и MAC в кэше соседей.
7. Запиши результаты четырьмя предложениями.

Если ты можешь объяснить назначение каждой команды и не запускаешь их вслепую, цель главы достигнута.
