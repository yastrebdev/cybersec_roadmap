# Ethernet, MAC и ARP

## Что даст эта глава

После чтения ты сможешь:

- объяснить работу локального Ethernet-сегмента;
- отличить MAC-адрес от IP-адреса;
- описать назначение коммутатора;
- объяснить, как ARP связывает IPv4 и Ethernet;
- читать вывод `ip link` и `ip neigh`.

## Локальная доставка

Представь две виртуальные машины в одной Host-only сети:

```text
Kali:          192.168.56.10
Metasploitable: 192.168.56.20
```

IP-адрес сообщает, какой узел нужен. Но Ethernet не отправляет кадр по IPv4-адресу. Для локальной доставки ему нужен MAC-адрес сетевого интерфейса.

Поэтому перед отправкой возникает вопрос:

> Какой MAC-адрес соответствует IP `192.168.56.20`?

На этот вопрос отвечает ARP.

## Что такое Ethernet

Ethernet — семейство технологий локальной сети. Он определяет формат кадров и правила передачи между сетевыми интерфейсами в одном канальном сегменте.

Упрощённый Ethernet-кадр содержит:

```text
[MAC назначения][MAC источника][тип][полезная нагрузка][контроль]
```

Полезной нагрузкой часто является IPv4-пакет.

Ethernet не знает, что такое веб-страница или SSH. Он решает более простую задачу: передать кадр следующему устройству в локальном сегменте.

## MAC-адрес

MAC-адрес — канальный идентификатор интерфейса. Обычно записывается шестью группами шестнадцатеричных чисел:

```text
08:00:27:12:34:56
```

У виртуальных машин VirtualBox часто встречается начало `08:00:27`, но полагаться на это как на доказательство нельзя: MAC можно изменить.

Посмотреть MAC-адреса Kali:

```bash
ip link
```

Краткий вывод конкретного интерфейса:

```bash
ip link show eth1
```

Фрагмент результата:

```text
link/ether 08:00:27:aa:bb:cc brd ff:ff:ff:ff:ff:ff
```

`link/ether` — MAC интерфейса. `ff:ff:ff:ff:ff:ff` — широковещательный MAC-адрес.

## Unicast, broadcast и multicast

**Unicast** — отправка одному конкретному интерфейсу.

```text
08:00:27:12:34:56
```

**Broadcast** — отправка всем интерфейсам в текущем широковещательном сегменте.

```text
ff:ff:ff:ff:ff:ff
```

**Multicast** — отправка группе подписанных получателей.

ARP-запрос отправляется broadcast, потому что отправитель пока не знает MAC нужного узла.

## Что делает коммутатор

Коммутатор, или switch, соединяет устройства внутри локальной сети. Он запоминает, какой MAC-адрес был замечен за каким портом.

Упрощённая таблица коммутатора:

| Порт | MAC-адрес |
|---|---|
| 1 | MAC Kali |
| 2 | MAC Metasploitable |
| 3 | MAC другого узла |

Если коммутатор знает MAC назначения, он пересылает кадр только на нужный порт. Если не знает — временно рассылает кадр по другим портам сегмента.

VirtualBox создаёт программный аналог такого канального сегмента. Физического кабеля нет, но логика Ethernet сохраняется.

## ARP: IP превращается в MAC

ARP расшифровывается как Address Resolution Protocol. Он используется IPv4-узлами для определения MAC-адреса соседа.

Пусть Kali хочет отправить пакет `192.168.56.20`.

### Шаг 1. Проверка подсети

Kali использует свой адрес и маску, чтобы понять: цель находится в той же подсети или в другой.

Если цель локальная, нужен MAC самой цели. Если цель удалённая, нужен MAC шлюза.

### Шаг 2. Проверка кэша соседей

```bash
ip neigh
```

Если соответствие IP и MAC уже известно, новый ARP-запрос не требуется.

### Шаг 3. ARP Request

Kali отправляет широковещательный запрос:

```text
Кто имеет 192.168.56.20?
Сообщите 192.168.56.10.
```

Его получают все устройства сегмента, но ответить должна машина с нужным IPv4-адресом.

### Шаг 4. ARP Reply

Metasploitable отвечает своим MAC-адресом:

```text
192.168.56.20 находится по адресу 08:00:27:12:34:56
```

### Шаг 5. Кэширование

Kali временно сохраняет соответствие в таблице соседей:

```text
192.168.56.20 dev eth1 lladdr 08:00:27:12:34:56 REACHABLE
```

Теперь IP-пакет можно поместить в Ethernet-кадр и отправить нужному MAC.

## Как читать `ip neigh`

Команда:

```bash
ip neigh
```

Пример:

```text
192.168.56.20 dev eth1 lladdr 08:00:27:12:34:56 STALE
```

| Поле | Значение |
|---|---|
| `192.168.56.20` | IPv4-адрес соседа |
| `dev eth1` | интерфейс, через который он доступен |
| `lladdr` | далее указан link-layer address |
| `08:00:27:12:34:56` | MAC-адрес |
| `STALE` | запись давно не подтверждалась |

Основные состояния:

- `REACHABLE` — сосед недавно подтвердил доступность;
- `STALE` — запись устарела, но это нормальное состояние;
- `DELAY` — ядро ждёт перед активной проверкой;
- `PROBE` — отправляются запросы проверки;
- `INCOMPLETE` — разрешение ещё не завершено;
- `FAILED` — MAC определить не удалось.

`STALE` не означает, что машина выключена. Это значит только, что запись давно не обновлялась.

## Что происходит при обращении в другую сеть

Пусть Kali имеет адрес `192.168.56.10/24`, а хочет обратиться к `8.8.8.8`.

Адрес `8.8.8.8` не входит в `192.168.56.0/24`. Поэтому Kali не ищет MAC `8.8.8.8`. Она ищет MAC своего шлюза и отправляет кадр ему.

```text
IP назначения:  8.8.8.8
MAC назначения: MAC локального шлюза
```

На каждом переходе Ethernet-заголовок может меняться. IP-адрес конечного назначения обычно остаётся тем же, если не учитывать NAT.

Это фундаментальное различие:

- MAC отвечает за ближайший локальный переход;
- IP отвечает за путь до конечной сети.

## Почему ARP важен для безопасности

Обычный ARP не имеет встроенной аутентификации. Узел может отправить ложное соответствие IP и MAC. На этом основаны атаки ARP spoofing и man-in-the-middle внутри локального сегмента.

Пока не нужно выполнять такие атаки. Важно понять предпосылку: устройства доверяют полученным ARP-сообщениям и обновляют локальный кэш.

За пределы текущего Ethernet-сегмента ARP-запросы обычно не проходят. Поэтому это локальный механизм и локальный класс риска.

## Практическое наблюдение

На Kali сначала посмотри текущих соседей:

```bash
ip neigh
```

Затем отправь один запрос Metasploitable:

```bash
ping -c 1 192.168.56.20
```

Снова выполни:

```bash
ip neigh
```

Найди появившийся IP, интерфейс, MAC и состояние записи.

Если установлен `tcpdump`, можно увидеть ARP напрямую:

```bash
sudo tcpdump -ni eth1 arp
```

В другом терминале очисти конкретную запись и снова обратись к цели:

```bash
sudo ip neigh del 192.168.56.20 dev eth1
ping -c 1 192.168.56.20
```

Останавливай `tcpdump` сочетанием `Ctrl + C`.

Команда удаления затрагивает только локальную запись кэша Kali. Ядро создаст её снова при следующем обращении.

## Что важно запомнить

- Ethernet доставляет кадры внутри локального сегмента.
- MAC-адрес принадлежит сетевому интерфейсу.
- Коммутатор пересылает кадры на основе MAC-адресов.
- ARP определяет MAC по IPv4-адресу.
- Для локальной цели нужен MAC цели.
- Для удалённой цели нужен MAC шлюза.
- `ip neigh` показывает кэш соседей, а не все устройства сети.
