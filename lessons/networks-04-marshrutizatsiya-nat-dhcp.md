# Маршрутизация, NAT и DHCP

## Что даст эта глава

После чтения ты сможешь:

- объяснить назначение маршрутизатора и шлюза;
- читать базовый вывод `ip route`;
- понимать разницу между Host-only, NAT и Bridged;
- объяснить, зачем используется NAT;
- описать получение настроек через DHCP.

## Когда нужен маршрутизатор

Если отправитель и получатель находятся в одной подсети, они общаются напрямую через локальную сеть.

Если получатель находится в другой подсети, отправитель передаёт пакет маршрутизатору. Маршрутизатор соединяет разные IP-сети и выбирает дальнейшее направление.

Пример:

```text
Kali:       192.168.56.10/24
Цель:       192.168.56.20/24
Удалённый:  8.8.8.8
```

`192.168.56.20` находится в локальной сети `192.168.56.0/24`. Kali отправляет кадр напрямую цели.

`8.8.8.8` находится в другой сети. Kali передаёт пакет шлюзу по умолчанию.

## Таблица маршрутизации

Операционная система выбирает путь по таблице маршрутизации:

```bash
ip route
```

Пример Kali с двумя интерфейсами:

```text
default via 10.0.2.1 dev eth0
10.0.2.0/24 dev eth0 proto kernel scope link src 10.0.2.15
192.168.56.0/24 dev eth1 proto kernel scope link src 192.168.56.10
```

Разберём строки.

```text
192.168.56.0/24 dev eth1
```

Сеть `192.168.56.0/24` доступна напрямую через `eth1`.

```text
10.0.2.0/24 dev eth0
```

Сеть `10.0.2.0/24` доступна напрямую через `eth0`.

```text
default via 10.0.2.1 dev eth0
```

Если более точного маршрута нет, пакет отправляется шлюзу `10.0.2.1` через `eth0`.

## Правило самого длинного префикса

Если подходят несколько маршрутов, выбирается наиболее конкретный — с самым длинным префиксом.

Допустим, есть:

```text
default via 10.0.2.1
192.168.56.0/24 dev eth1
```

Для `192.168.56.20` подходит и default-маршрут `/0`, и маршрут `/24`. Победит `/24`, потому что он точнее.

## Шлюз по умолчанию

Шлюз по умолчанию — соседний маршрутизатор, которому узел передаёт пакеты для неизвестных сетей.

Шлюз должен быть доступен в локальном канальном сегменте. Чтобы отправить ему кадр, система определяет его MAC через ARP.

Проверить выбранный путь до конкретного адреса:

```bash
ip route get 8.8.8.8
```

И до Metasploitable:

```bash
ip route get 192.168.56.20
```

Команда покажет интерфейс, шлюз и исходный IP, которые выберет ядро.

## Что происходит на маршрутизаторе

Упрощённо маршрутизатор:

1. Получает Ethernet-кадр.
2. Извлекает IP-пакет.
3. Проверяет IP назначения.
4. Уменьшает TTL.
5. Выбирает следующий маршрут.
6. Создаёт новый кадр для следующего канала.

Если TTL становится равным нулю, пакет отбрасывается. Это предотвращает бесконечное хождение пакетов по петле маршрутов.

## Traceroute

`traceroute` пытается показать промежуточные маршрутизаторы:

```bash
traceroute 8.8.8.8
```

Он отправляет пакеты с постепенно увеличивающимся TTL. Маршрутизаторы, на которых TTL заканчивается, возвращают ICMP-сообщения.

Не все узлы отвечают, поэтому звёздочки в выводе не обязательно означают поломку.

Для Host-only цели обычно нет промежуточного маршрутизатора:

```bash
traceroute 192.168.56.20
```

## NAT

NAT — преобразование сетевых адресов. В домашней сети и VirtualBox чаще всего используется преобразование частных адресов в адрес внешнего интерфейса.

Пусть Kali отправляет запрос:

```text
Источник:    10.0.2.15:49152
Назначение:  203.0.113.10:443
```

Устройство NAT заменяет исходные данные на свои внешние:

```text
Источник:    внешний_IP:новый_порт
Назначение:  203.0.113.10:443
```

NAT запоминает соответствие. Когда приходит ответ, он возвращает внутренние адрес и порт.

Это позволяет нескольким внутренним устройствам использовать один внешний IPv4-адрес.

NAT не является полноценной заменой межсетевого экрана. Он изменяет адреса, а firewall принимает решения о разрешении или блокировке трафика.

## Сетевые режимы VirtualBox

### NAT

Виртуальная машина может обращаться наружу через механизм VirtualBox. Подключения извне к гостю обычно требуют отдельной настройки проброса портов.

Подходит для:

- обновлений Kali;
- установки пакетов;
- доступа в интернет из гостевой системы.

### NAT Network

Несколько виртуальных машин подключаются к общей NAT-сети и могут общаться между собой в зависимости от настройки. У них также может быть выход наружу.

Намеренно уязвимую машину лучше не подключать сюда без необходимости.

### Host-only

Создаётся отдельная сеть между хостом и виртуальными машинами. Прямого выхода в интернет через этот интерфейс нет.

Подходит для:

- Kali и Metasploitable;
- изолированных лабораторий;
- анализа трафика между виртуальными машинами.

### Bridged

Виртуальная машина оказывается в той же сети, что и физический компьютер. Она может быть доступна другим домашним устройствам.

Для намеренно уязвимой Metasploitable этот режим использовать не следует.

## DHCP

DHCP автоматически выдаёт сетевые настройки:

- IPv4-адрес;
- маску;
- шлюз по умолчанию;
- DNS-серверы;
- срок аренды адреса.

Без DHCP пришлось бы задавать всё вручную.

## Процесс DORA

Классический обмен DHCPv4 часто описывают четырьмя шагами.

### Discover

Клиент ещё не знает своей сети и ищет DHCP-сервер широковещательным сообщением.

### Offer

Сервер предлагает адрес и параметры.

### Request

Клиент просит использовать выбранное предложение.

### Acknowledge

Сервер подтверждает аренду.

Сокращение первых букв даёт DORA: Discover, Offer, Request, Acknowledge.

## DHCP в VirtualBox

Для Host-only сети VirtualBox может запустить встроенный DHCP-сервер. Тогда Kali и Metasploitable получают адреса автоматически.

Адреса могут отличаться от примеров:

```text
Kali:          192.168.56.101
Metasploitable: 192.168.56.102
```

Поэтому не следует слепо записывать `.10` и `.20`. Всегда проверяй фактические адреса:

```bash
ip -br addr
```

На старой Metasploitable:

```bash
ifconfig
```

## Статический адрес и DHCP

DHCP удобен для начала, но адрес может измениться. Статический адрес удобен для постоянной лаборатории, но требует ручной настройки и контроля конфликтов.

Для первых занятий оставь DHCP. Зафиксируй выданные адреса в заметках перед практикой.

## Практическое наблюдение

На Kali выполни:

```bash
ip -br addr
ip route
```

Для каждого маршрута ответь:

1. Какая сеть указана?
2. Через какой интерфейс она доступна?
3. Какой исходный IP используется?
4. Есть ли шлюз?

Затем сравни маршруты:

```bash
ip route get 192.168.56.20
ip route get 8.8.8.8
```

Первый должен идти через Host-only интерфейс. Второй — через NAT и шлюз по умолчанию.

## Что важно запомнить

- Маршрутизатор соединяет разные IP-сети.
- Локальная подсеть доступна напрямую.
- Для других сетей обычно используется шлюз по умолчанию.
- Побеждает наиболее конкретный подходящий маршрут.
- NAT преобразует адреса и часто порты.
- DHCP автоматически выдаёт сетевые параметры.
- Kali может иметь NAT и Host-only одновременно.
- Metasploitable безопаснее оставлять только в Host-only.
