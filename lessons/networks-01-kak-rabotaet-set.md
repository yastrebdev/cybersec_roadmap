# Как работает сеть

## Что даст эта глава

После чтения ты сможешь:

- объяснить, что такое узел, канал, протокол и пакет;
- отличить локальную сеть от интернета;
- описать путь данных по уровням TCP/IP;
- объяснить, зачем нужны MAC-адрес, IP-адрес и порт;
- читать простую схему сети без ощущения хаоса.

Не пытайся сразу запомнить все названия. Главная задача — увидеть общую картину.

## Сеть как система доставки

Компьютерная сеть — это набор устройств, которые обмениваются данными по согласованным правилам.

Для обмена нужны четыре элемента:

1. Отправитель.
2. Получатель.
3. Канал связи.
4. Правила обмена.

Отправителем может быть браузер на Kali, получателем — веб-сервер Metasploitable. Каналом будет виртуальная сеть VirtualBox. Правилами будут Ethernet, IP, TCP и HTTP.

Правила обмена называются **протоколами**. Каждый протокол решает ограниченный набор задач. Один определяет адрес устройства в локальной сети, другой доставляет пакет между сетями, третий обеспечивает надёжное соединение, четвёртый описывает веб-запрос.

## Основные термины

| Термин | Значение |
|---|---|
| Узел, или host | Устройство, участвующее в сети |
| Интерфейс | Точка подключения устройства к сети |
| Канал | Среда передачи: кабель, Wi-Fi или виртуальный адаптер |
| Протокол | Согласованные правила обмена |
| Пакет | Порция данных, передаваемая по сети |
| Адрес | Идентификатор отправителя или получателя |
| Маршрут | Правило выбора следующего направления |
| Сервис | Программа, принимающая сетевые запросы |

Один компьютер может иметь несколько интерфейсов и несколько адресов. У Kali, например, может быть `eth0` для NAT и `eth1` для Host-only сети.

## Локальная сеть и интернет

Локальная сеть, или LAN, объединяет устройства в пределах одного логического сегмента. В домашней сети это ноутбуки, телефоны и роутер. В лаборатории — Kali, Metasploitable и виртуальный адаптер Windows.

Устройства одной подсети обычно могут общаться напрямую. Если получатель находится в другой сети, пакет передаётся маршрутизатору.

Интернет — это не одна большая сеть. Это множество сетей, связанных маршрутизаторами.

Упрощённая схема лаборатории:

```text
Интернет
   |
[NAT VirtualBox]
   |
eth0: Kali

Windows host-only adapter
   |
   +---- eth1: Kali
   |
   +---- eth0: Metasploitable
```

Metasploitable находится только в Host-only сегменте. Kali одновременно подключена к лаборатории и к NAT для обновлений.

## Зачем данные делятся на пакеты

Сеть не отправляет большой файл одним непрерывным куском. Данные делятся на небольшие блоки. К каждому блоку добавляется служебная информация:

- кто отправитель;
- кто получатель;
- какой протокол используется;
- к какому соединению относятся данные;
- в каком порядке их собрать;
- не были ли они повреждены.

Такую порцию данных в разговорной речи часто называют пакетом. На разных уровнях используются более точные термины: кадр, IP-пакет, TCP-сегмент и сообщение приложения.

## Модель TCP/IP

Чтобы не смешивать все задачи, сетевое взаимодействие делят на уровни.

| Уровень TCP/IP | Примеры | Главный вопрос |
|---|---|---|
| Прикладной | HTTP, DNS, SSH | Что хотят передать программы? |
| Транспортный | TCP, UDP | Какому приложению доставить данные? |
| Межсетевой | IPv4, IPv6, ICMP | Как доставить пакет до нужного узла? |
| Канальный | Ethernet, Wi-Fi, ARP | Как передать данные соседу в текущей сети? |

Физическая передача электрических или радиосигналов иногда рассматривается отдельно.

### Прикладной уровень

Это уровень программ, с которым пользователь сталкивается напрямую.

Браузер создаёт HTTP-запрос:

```text
GET / HTTP/1.1
Host: 192.168.56.20
```

SSH-клиент создаёт сообщения протокола SSH. DNS-клиент формирует запрос имени. Каждый протокол имеет собственный формат.

### Транспортный уровень

TCP или UDP добавляет номера портов. Благодаря портам операционная система понимает, какой программе передать данные.

Пример:

```text
Источник: порт 49152
Назначение: порт 80
```

Порт `80` обычно связан с HTTP. Порт источника временно выбирает клиентская система.

### Межсетевой уровень

IP добавляет адреса узлов:

```text
Источник: 192.168.56.10
Назначение: 192.168.56.20
```

Маршрутизаторы читают адрес назначения и выбирают дальнейший путь.

### Канальный уровень

Ethernet добавляет MAC-адреса для доставки внутри текущего сегмента:

```text
MAC отправителя: 08:00:27:aa:aa:aa
MAC получателя:   08:00:27:bb:bb:bb
```

MAC-адрес нужен для ближайшего перехода. IP-адрес описывает конечное направление между сетями.

## Инкапсуляция

Когда браузер отправляет запрос, каждый уровень добавляет свой заголовок:

```text
Ethernet [ IP [ TCP [ HTTP [ данные ] ] ] ]
```

Этот процесс называется **инкапсуляцией**.

На принимающей стороне происходит обратное:

1. Сетевая карта принимает Ethernet-кадр.
2. Операционная система извлекает IP-пакет.
3. Из IP-пакета извлекается TCP-сегмент.
4. TCP передаёт данные процессу, слушающему нужный порт.
5. Веб-сервер разбирает HTTP-запрос.

Полезная модель: каждый уровень разговаривает со своим уровнем на другой машине, но использует нижние уровни для доставки.

## OSI и TCP/IP

В учебных материалах часто используется семиуровневая модель OSI.

| OSI | TCP/IP | Примеры |
|---|---|---|
| 7. Прикладной | Прикладной | HTTP, DNS, SSH |
| 6. Представления | Прикладной | кодирование, форматы, шифрование |
| 5. Сеансовый | Прикладной | управление сеансом |
| 4. Транспортный | Транспортный | TCP, UDP |
| 3. Сетевой | Межсетевой | IP, ICMP |
| 2. Канальный | Канальный | Ethernet, ARP |
| 1. Физический | Канальный/физический | кабель, радио, сигнал |

OSI удобна для диагностики и общения. TCP/IP ближе к реальному устройству интернета. Не нужно спорить, какая модель правильнее: они используются для разных объяснений.

## Как мыслить при неисправности

Проверяй снизу вверх:

1. Интерфейс включён?
2. IP-адрес назначен?
3. Есть маршрут до сети?
4. Доступен сосед или шлюз?
5. Открыт нужный порт?
6. Правильно ли работает приложение?

Если веб-страница не открывается, причина не обязательно в браузере. Возможно, интерфейс выключен, указан неправильный маршрут, не отвечает DNS или сервер не слушает порт.

## Мини-наблюдение в Kali

Посмотри интерфейсы:

```bash
ip -br addr
```

Посмотри маршруты:

```bash
ip route
```

Посмотри открытые локальные сокеты:

```bash
ss -lntup
```

Пока не нужно запоминать весь вывод. Найди интерфейс, IP-адрес, маршрут своей Host-only сети и несколько локальных портов.

## Что важно запомнить

- Сеть — это устройства, каналы и протоколы.
- Протокол решает конкретную задачу, а не всё сразу.
- Данные проходят через несколько уровней.
- MAC используется в локальном сегменте.
- IP используется для адресации между сетями.
- Порт связывает сетевой трафик с приложением.
- Диагностика начинается с нижних уровней.

## Самопроверка

Ответь своими словами:

1. Чем протокол отличается от программы?
2. Почему одному компьютеру может принадлежать несколько IP-адресов?
3. Зачем одновременно нужны IP-адрес и порт?
4. Что означает инкапсуляция?
5. Какой уровень отвечает за HTTP, а какой — за IP?
6. Почему интернет правильнее представлять как сеть сетей?

Если ответы пока неточные — это нормально. Следующие главы разберут каждый слой отдельно.
